    Release Notes v0.7.0¶

    Released: 2026-11-12

    An outcome model now becomes one document for people to read. Choose the views and their order, or a profile such as nonprofit, and get Markdown, a Word document, or a single-file HTML presentation, with every diagram drawn. The document opens with the organization's background, from who it is to how the views that follow serve its mission and vision, all drawn from the model.

    The theory of change and logic model diagrams are redrawn to be read on a page: bottom-up, a band per stage, boxes of one width that line up, and arrows routed around the boxes, never over them.

    This release adds to the API and changes no document: a v0.6.0 model reads unchanged. See Upgrading for the diagrams whose output changes.

    Highlights¶

    • Documents and presentations. export document writes the sections you choose, in order, as Markdown, Word, or an HTML presentation, with an outcome_document MCP tool alongside.
    • A background that opens every document. Who the organization is, its vision, mission, and values, its programs and their activities, and how the document serves the mission and vision, from the new context.background and the rest of the model.
    • Readable diagrams. The theory of change, for the whole model and for each pathway, and the logic models are drawn bottom-up with ELK, with wrapped labels and no arrow over a box.
    • Reproducible Word and PowerPoint files. The same model and date give the same bytes.

    New Features¶

    One document from the model¶

    outcome-model export document outcome-model.yaml --out plan.docx
outcome-model export document outcome-model.yaml --profile strategy --out strategy.html
outcome-model export document outcome-model.yaml --sections background,theory-of-change,vsem,mel --out plan.md

    The format follows the --out extension. A profile names a common list of sections, and --sections gives your own, in order:

    Profile Sections
    nonprofit (the default) background, theory-of-change, logic-models, vsem, mel, glossary
    strategy background, theory-of-change, vsem, ogsm
    evaluation background, theory-of-change, logic-models, logframe, metrics, mel
    improvement background, problem-trees, dmaic
    full every section

    Each section's headings sit one level below its own, so the document reads as one. The VSEM, OGSM, MEL, and DMAIC sections come from prism-roadmap's Markdown renderers. A section the model cannot be drawn as is an error, or, with --skip-unavailable, is left out and listed. Markdown output writes each diagram as SVG in a folder beside it, or keeps the D2 source with --diagrams d2; Word goes through Pandoc, styled with --reference-doc. See Documents and presentations.

    The outcome_document MCP tool returns the same document as Markdown, with the diagrams as D2 blocks and any skipped sections listed. In Go, service.Document builds it and the document package writes it.

    The HTML presentation¶

    The .html output is one file that opens in a browser: a title slide, a contents slide, a divider for each section, a slide for each heading, and a full slide for each diagram. Long text and tables run on to further slides, with a table's header repeated. The arrow keys, Page Up and Down, Space, Home, and End move between slides, and the address keeps the slide number. A diagram whose labels would be too small once fitted to the slide is shown at a readable width and the slide scrolls. Open it with ?print to lay every slide out as a 1280×720 page for printing to PDF.

    The background¶

    A document opens with a background for a reader new to the organization:

    • About the organization: context.background, a new field of plain paragraphs separated by a blank line, or else the description of the perspective's actor; then whom it serves, where, and the model's period.
    • Vision, mission, and values, from the context.
    • Programs: each pathway that is not rejected, with its description and activities.
    • How this document serves the mission and vision: the impact outcomes the vision is reached through, the objective, the ceiling of accountability, and a table of the sections that follow and what each shows.
    context:
  background: |-
    Riverbend Nonprofit Network began in 2015, when a dozen nonprofit
    directors started meeting to share back-office costs. ...

    The network runs leadership cohorts and peer circles, ...

    Diagrams to read on a page¶

    • The theory of change on one page. A new theory-of-change-d2 report draws the activities and outcomes of every pathway, or of one with --pathway, from short term to impact. Inputs and outputs are left to the logic model, and each activity is joined to the outcomes its outputs lead to. The document draws the whole model, then each pathway.
    • Bottom-up, routed, and aligned. The theory of change and the logic-model-d2 diagram are drawn a band per stage with the impact on top, laid out with ELK so arrows go around boxes. Every box in a diagram is one width, so boxes line up in columns, with labels wrapped to suit it; a diagram with a wide stage gets narrower boxes. A pathway's theory of change reads at about 8 points or more on a portrait Word page. The Mermaid logic-model-layered diagram stays left to right for slides, with wrapped labels.
    • Rendering. The document export draws diagrams with the d2 tool, with a 20-pixel margin and tighter ELK spacing, so labels stay larger once fitted to a page. Check any rendered diagram with d2vision legibility diagram.svg.

    Reproducible Word and PowerPoint¶

    export docx, export pptx, and the Word document from export document now give the same bytes for the same model and date: Pandoc runs with SOURCE_DATE_EPOCH set from --as-of (or 1 January 1980), the zip entries' times are fixed, and images are referred to by name rather than by a temporary path.

    Fixes¶

    • Graphviz refused the DOT output. graph --format dot named the graph outcome-model, which DOT does not accept unquoted. The name is now quoted.

    Documentation¶

    • A documents and presentations guide: the formats, profiles and sections, the background, how diagrams are drawn to be read, and the presentation.
    • The reports guide lists theory-of-change-d2 and describes the bottom-up logic-model-d2; the CLI and MCP guides list export document and outcome_document; the concepts page names context.background.
    • The PRD, TRD, and roadmap specify documents and presentations (PRD-FR-608 and 609, TRD-046 to 049, §6.20, Phase 31).

    Installation¶

    go install github.com/ProductBuildersHQ/outcome-model/cmd/outcome-model@v0.7.0

    Go 1.26.5 or later. The module requires prism-roadmap v0.26.0 and d2vision v0.6.0.

    export document needs the d2 tool to draw diagrams, except Markdown with --diagrams d2, and Pandoc for Word. Without a tool it needs, nothing is written and the exit code is 3.

    Upgrading¶

    No document changes: specVersion stays "0.1", and context.background is optional. Go code compiles unchanged; an API comparison with v0.6.0 reports only additions.

    Some output changes:

    • logic-model-d2 is drawn bottom-up with ELK, which the D2 source names in its d2-config, in place of a grid of columns. Rendering it needs a d2 with ELK, which d2 bundles.
    • logic-model-layered (Mermaid) wraps long labels with <br/> and draws each stage as a light band.
    • graph --format dot quotes the graph name: digraph "outcome-model".
    • export docx and export pptx files no longer differ from run to run, so a file compared or committed before changes once.

    Known Limitations¶

    • The whole model's theory of change is a map. With many activities, its labels are small on a page; read the detail in each pathway's.
    • A logic model with many outputs reads small on a portrait page, since its outputs sit side by side. Its table, beside the diagram, has the same content.
    • Boxes line up within a stage, not always across stages. ELK shifts a stage sideways to keep arrows straight, and d2 exposes no setting to stop it.
    • context.background is plain text. Paragraphs are kept; Markdown in it is not interpreted.
    • The HTML presentation loads React from cdnjs, so it needs a network connection the first time it opens.
    • The limitations of v0.6.0 still apply.
